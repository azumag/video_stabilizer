# Phase 0 実機確認手順

## 事前確認

```bash
npm install
npm run check
```

`dist/video-stabilizer`をChromeの「パッケージ化されていない拡張機能」として読み込む。

## 必須ケース

各ケースで、日時、Chromeバージョン、OS、Twitch URL、ログイン有無、画質設定を記録する。

### 1. ライブ配信

- Twitchの通常のライブ配信を開く
- 10秒以上再生する
- 診断パネルの解析フレーム数が増えることを確認する
- `Canvas / Worker / WASM`の結果を記録する

### 2. VOD

- 過去配信を開く
- 再生、一時停止、シークを行う
- シーク後に追跡状態が復帰することを確認する

### 3. 表示モード

- 通常表示
- シアターモード
- フルスクリーン

それぞれで同じ映像要素を追跡し続けるか確認する。

### 4. 画質変更

- 自動画質から720pまたは1080pへ変更する
- `videoWidth`変更後に解析サイズが更新されることを確認する
- 追跡がリセットされ、その後復帰することを確認する

### 5. 広告境界

広告が表示された場合、広告中と配信復帰後のCanvas結果をそれぞれ記録する。広告への完全対応はPhase 0の完了条件ではない。

### 6. 補正適用

- ポップアップから「補正を画面へ適用」をONにする
- 手持ちカメラ等の小さな揺れがある配信で確認する
- OFFに戻したとき、Twitch本来の表示位置へ即座に戻ることを確認する
- ページ遷移後に古い変換が残らないことを確認する

## 合格条件

### Canvas

- 通常のライブまたはVODの少なくとも一方で`getImageData()`が継続成功する
- 失敗時には`SecurityError`等の理由が診断へ表示される

### Worker/WASM

- Workerが3秒以内に`ready`を返す
- `probe.wasm`の結果が42になる
- 30秒以上解析してWorkerが停止しない

### 処理負荷

初期目標であり、厳密なリリース基準ではない。

- 320px・15fps設定で平均処理時間が66ms未満
- Worker処理中にフレームキューを積まない
- Twitchの音声と操作UIが維持される

## 結果の分類

### A: 主方式を継続

Canvas、Worker、WASMがすべて成功する。

### B: 条件付き継続

ライブまたはVODの一部だけCanvas取得できる。対応範囲を明記し、成功ケースでPhase 1へ進む。

### C: 方式変更

通常のライブとVODの双方でCanvas取得できない。`chrome.tabCapture`を使う別表示方式の設計へ移る。
